# AI Native Call Center API TypeScript SDK

> **Unofficial demo.** Generated by [Octri](https://octri.dev) from AI Native Call Center's OpenAPI specification ([`docs/openapi.json` at rasonyang/ai-native-callcenter@a3ccde1](https://github.com/rasonyang/ai-native-callcenter/blob/a3ccde1e3764e3dcc9c6a9761377ca24628e80a5/docs/openapi.json)). Not affiliated with or endorsed by the AI Native Call Center project. Not a production release and not published to npm.

Project: [AI Native Call Center](https://github.com/rasonyang/ai-native-callcenter)

The single contract for every HTTP endpoint the platform serves. Spec-first: this document is the source of truth; Go and TypeScript types are generated from it, never the other way around. The embedded web application is one consumer of this contract, with no route and no capability of its own.

Naming follows docs/design/07-naming.md: JSON properties are lowerCamelCase with initialisms treated as words (callId), enum values are SCREAMING_SNAKE_CASE and byte-identical across JSON, TypeScript and the database, timestamps are xxxAt (RFC 3339), durations are xxxSec/xxxMs, booleans are is/has prefixed.

**Authorization is scopes, not roles.** Every operation declares the scopes it needs; the vocabulary is x-scopes at the root of this document and nothing else defines it. Two credentials carry those scopes and neither is the norm: a person signs in at a browser and gets a session cookie (POST /auth/login), whose scopes are derived from the account's role — the role itself never reaches the wire; a system presents an API key as `Authorization: Bearer <key>` and carries exactly the scopes it was issued with. A key may act for an agent by sending `X-AICC-Agent-ID`; the same header on a session request is refused. A mutating request that authenticates with the cookie must also carry X-AICC-Csrf; one that authenticates with a key must not — that header protects a credential the browser sends automatically.

Errors always use the single envelope {"error": {code, message, params}}; the code is machine-readable and localized by the client. That holds for the router's own refusals too: a path this contract does not declare is 404 NOT_FOUND and a method it does not declare on a path it does is 405 METHOD_NOT_ALLOWED, both in the envelope — never the web application's index.html, which a client cannot tell from a successful response.

A separate unauthenticated operations listener (AICC_METRICS_ADDR, default 127.0.0.1:9090) serves GET /metrics, /healthz and /readyz in plain text; it is deliberately outside this contract.

## Quickstart

The example calls `client.catalog.createQueue` (POST `/queues`) with example values for its required arguments. Replace `https://api.example.com` with your server's URL.

```ts
import { AINativeCallCenter } from "ai-native-call-center-api";

async function main() {
  const client = new AINativeCallCenter({
    // Required: the API declares no server with a host, so set your instance's URL.
    baseUrl: "https://api.example.com/api/v1",
    auth: { apiKeyBearer: process.env.API_TOKEN! },
  });
  const result = await client.catalog.createQueue({ name: "Example Name" });
  console.log(result);
}

main().catch(console.error);
```

## Authentication

Keep credentials outside source control. The quickstart reads them from the environment and the client sends each one only on the operations whose security requirement accepts its scheme.

| Scheme        | ClientAuth field | Sent as                   |
| ------------- | ---------------- | ------------------------- |
| cookieSession | `cookieSession`  | `aicc_session` in cookie  |
| csrfHeader    | `csrfHeader`     | `X-AICC-Csrf` in header   |
| apiKeyBearer  | `apiKeyBearer`   | `Authorization: Bearer …` |

## Client behavior

- Base URL: set it in `ClientConfig` before the first request.
- Transport: Fetch API.
- Timeout: 30,000 ms per attempt.
- Retries: up to 3 attempts for status codes `408`, `425`, `429`, `500`, `502`, `503`, `504`, with 500–8,000 ms backoff.
- Idempotency: enabled for `POST`, `PATCH` using `Idempotency-Key`.
- Error telemetry: off. This build has no reporting endpoint and sends no error reports.

High-level operation methods return the typed response body directly. The low-level request layer returns an `SdkResponse<T>` envelope containing data, status, headers, request ID, latency, and attempt count.

## Errors and response metadata

All failure paths use a small, predictable hierarchy:

| Error                    | Meaning                                                                                                                      |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| `SdkValidationError`     | A request argument failed an OpenAPI constraint before network I/O.                                                          |
| `SdkHttpError`           | The server returned a non-2xx response.                                                                                      |
| `SdkApiError`            | A 2xx response whose error envelope, when the API declares one, reports a failed call. It carries the envelope's error code. |
| `SdkResponseDecodeError` | A 2xx response body or stream event did not decode into its declared type. It keeps the raw body.                            |
| `SdkNetworkError`        | DNS, connection, TLS, or socket failure.                                                                                     |
| `SdkTimeoutError`        | The configured per-attempt timeout elapsed.                                                                                  |

HTTP errors expose `statusCode`, the response body and headers, plus `requestId` when the server supplies one. Preserve the request ID in support logs; it is the fastest way to correlate a failed SDK call with server-side traces.

Common statuses are reported as a subclass of `SdkHttpError`, so a handler can catch only the one it handles: `SdkBadRequestError` (400), `SdkUnauthorizedError` (401), `SdkPermissionDeniedError` (403), `SdkNotFoundError` (404), `SdkConflictError` (409), `SdkUnprocessableEntityError` (422), `SdkRateLimitError` (429), `SdkInternalServerError` (any 5xx). Any other status is reported as `SdkHttpError` itself.

When the API declares a model for an error response, the SDK decodes the body into it as `error.data`, typed as the `SdkErrorBody` union of those models. It is empty when the status declares no model or the body does not fit one. The raw body stays on the error either way, and `deserializeModel<ErrorModel>(error.body, "ErrorModel")` decodes it into any `ErrorModel` by hand.

An operation that declares error models also exports `<Operation>Error`, the union of those models, for typing a decoded body.

## Streaming

1 operation streams Server-Sent Events as `AsyncIterable<T>`. The runtime handles SSE framing, ignores keep-alive comments, and treats `[DONE]` as the terminal marker. Cancel or stop iteration when the consumer no longer needs events so the underlying connection can close promptly.

## Project layout and API discovery

- Operation implementations are grouped under `src/methods/`.
- 184 component models are split by API domain under `src/types/<domain>.ts` or `src/types/<tag path>/models.ts`, re-exported by `src/types/index.ts` and the package root.
- Component schemas can choose a nested model folder with `x-octri-sdk-tags: ["Billing/Invoices"]`; the first tag owns the model and `/` creates nesting.
- [`sdk-manifest.json`](sdk-manifest.json) is the language-neutral public API index: operations, request/response modes, model properties, enum values, and generation settings.
- Public barrel/module exports are the compatibility boundary. Import public model names from those exports; internal domain filenames may evolve without changing model names.

## Local mock-server tests

The generated SDK includes a schema-derived, zero-dependency mock server and a
network contract suite. Node.js 20+ is required. Contract probes use authored response
examples only; schema-synthesized routes remain available to the local server.

`./scripts/mock --port 4010` starts the server. `./scripts/test` runs the mock contract suite, then native SDK tests. A zero-authored-example contract run succeeds with an explicit zero-test
summary; mismatches in authored examples still fail.
